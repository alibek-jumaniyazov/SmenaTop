# Mobile usability review

Reviewed on 2026-09-23 from the source before the visual redesign. This is a focused implementation review, not a browser, assistive-technology or accessibility certification result. The references below describe the reviewed baseline; line numbers may move during the redesign. No application code was changed for this review.

## Existing behavior to retain

The shared native dialog already implements Escape dismissal, focus trapping and focus restoration. The phone form has explicit error association, loading and error components use status/alert semantics, and mobile bottom navigation accounts for the safe area. Keep these patterns while changing the visual language. Loading, empty, pending, failure and success states remain part of every redesigned workflow.

## Landing content and interaction review

Compared `pages/Landing.tsx` and `pages/landing-copy.ts` with the master prompt's product, design, booking and payment semantics. The final source retains explicit interactive-sample and calendar-example labels, actual API-backed category filtering, direct employer wage payment, separate employer subscriptions and the statement that finding a worker is not guaranteed. It does not introduce fictitious customers, live usage figures, provider capabilities or a payroll promise.

Four refinements were raised and then confirmed in the updated source:

- The public list originally implied nearby, schedule-matched recommendations despite requesting only category and pagination. The copy now asks users to compare time, address and conditions, without claiming personalization.
- The acceptance FAQ now states in both languages that an offer does not reserve a place, and acceptance depends on an active offer and remaining capacity.
- Catalogue failure now has a localized explanation and an actual retry control while the independent shift list can remain available.
- The planner's polite, atomic live region now includes the selected period and interval, so its announced content changes when a time option is chosen.

The sample planner changes demonstration state only. Neither its confirmation text nor its time buttons call a booking endpoint. Navigation actions link to actual search, authentication, pricing and help routes. Browser verification is recorded separately; these statements are source-review evidence.
